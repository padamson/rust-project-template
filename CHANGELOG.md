# Changelog

All notable changes to this project are documented here.
The format is based on [Keep a Changelog](https://keepachangelog.com/).

## [Unreleased]

### Added
- `dependabot.yml`: a commented `directories:` example on the cargo entry, for repos whose excluded crates commit their own `Cargo.lock` (Dependabot reads only the root lock otherwise)
- `.config/nextest.toml`: slow-timeout and leak-timeout in every profile, retries only under `[profile.ci]` (which CI now runs), a commented test-group example; every CI job carries `timeout-minutes`
- `.cargo/mutants.toml` ships live instead of as an `.example`, so a fresh clone never runs mutation testing unscoped under `cargo test`
- Seed crate rewritten as claim-shaped tests: `classify` returns a `Size` enum with a boundary at the threshold and a `SizeError::Negative` variant carrying the count; the threshold reads the environment through an injected lookup; `tests/common/mod.rs` ships a `TempDir`-owning `Workspace` fixture and a bounded `poll_until`; one `#[ignore = "..."]` test shows the gate for anything a fresh clone may lack. `tempfile` as a dev-dependency
- Doctest policy: `cargo test --doc` always runs, and the crate keeps at least one doctest so the step is honest
- CLAUDE.md "Tests" section with the shapes and the runner policy
- `scripts/mutants.sh` creates its scratch diff under `$TMPDIR` with a full template; `mktemp -t` ignores `$TMPDIR` on macOS and fails under the Claude Code sandbox
- `release.yml` gates the release on `cargo semver-checks check-release`: a job the publish waits on, comparing each publishable crate with its latest crates.io release and skipping a crate crates.io answers 404 for (any other answer fails the run). Crates without a library target are listed and passed over. The publish skips a version already on crates.io, so the first tag after the hand-published first version goes green. Both crates.io probes retry a refused connection or failed lookup as well as a 5xx, time out each attempt after 30 seconds, and report a connection that never answered as an error line rather than a bare exit code
- `release.yml` opens with a `Release references` job that the semver check, the build matrix and the supply-chain gates all wait on, so a mistake in a hand-written version fails the run in under a minute: a tag no publishable crate's version matches, and a crate at the tag's version that requires a workspace sibling at anything but that sibling's full current version (a stale requirement that cargo lets through on a patch bump)
- `release.yml` publishes to crates.io with Trusted Publishing (OIDC via `rust-lang/crates-io-auth-action`); the token-missing skip and the `continue-on-error` on the publish step are gone, since both made a failed publish look green. SETUP.md walks through the crates.io publisher entry, and SETUP.md and CLAUDE.md give the `audit-as-crates-io = false` cargo-vet policy each crate needs after its first publish
- Advisories in every tracked `Cargo.lock` checked by cargo-lockpatrol, pinned by SHA: it runs in the `Security & Quality` gate (through the shared `supply-chain.yml`) and, in `advisory-monitor.yml`, a daily monitor that keeps one tracking issue current and closes it when every tree is clean; its prek hook runs the same release on commits that touch a manifest, a lock or `deny.toml`. A root `Cargo.lock` that disagrees with its manifests fails the check as broken. `dependabot.yml` has a `pre-commit` entry, so the hook's rev moves with the monitor's action
- `cargo audit` removed from CI and the hooks: `cargo deny check` reads the same advisory database, so `deny.toml`'s `[advisories] ignore` is the single list and nothing mirrors it. `Security Audit` leaves the required checks
- Every action in every workflow pinned to a commit SHA with the version in a trailing comment (Dependabot keeps them current); workflow permissions default to `contents: read` and each writing job names what it writes
- `.github/actions/diff-base`: a composite action giving the skill-guard job the PR base branch's current tip, the push's previous tip, or nothing on a first push
- Agent skill scaffold: `skills/my-project/` with `references/`, hidden from installers by `metadata.internal: true` until shipped; `scripts/check-skill-version-bumped.sh` as a pre-commit hook and a `Skill version guard` CI job; the `npx skills add` block plus skills.sh badge in README.md. SETUP.md says how to ship it (with the in-repo symlink as an opt-in for crates that use themselves) or remove it
- Consumed agent skills: `.agents/` and the entries of `.claude/skills/` gitignored (the entries, not the directory, so the `!/.claude/skills/<name>` an in-repo skill adds takes effect), and a CLAUDE.md section on `npx skills add` installs (from a plain terminal) and `npx skills update -p` refreshes (fine inside the sandbox)
- Tracked `.claude/settings.json` with the Claude Code sandbox block (loopback network, configd Mach lookup, excluded commands for git, gh, nextest, cargo run, prek, and the mutants script)
- CLAUDE.md states the sandbox is on for every repo and cross-repo writes are not allowed; SETUP.md says `prek install` writes `.git/hooks` and is run by hand once per clone
- Dual license, `MIT OR Apache-2.0`: `LICENSE-MIT` and `LICENSE-APACHE`, `Cargo.toml` and README updated
- SETUP.md: keeping `target/` under control (a `find` that lists Cargo-made `target/` directories idle 30 days, since cargo-sweep is unmaintained; turning incremental off, build-script assets outside `OUT_DIR` with their own CI cache), converting to a workspace, and a `build.rs` recipe so `--version` reports the build commit off a release tag. The recipe finds a lightweight release tag beside an annotated one, calls git only in the crate's own checkout, re-runs after a commit, a `git gc`, a new tag, or in a worktree, and warns when git fails in a checkout. Its decision is a pure function unit-tested without git, with a `release.yml` step that checks the shipped binary prints the bare version
- Pre-commit: a comment by the nextest hook stating that the hook's feature set must equal the union of CI's, and a commented `exclude:` for byte-exact fixture directories on the whitespace hooks
- `security.yml`: a commented resolve-then-`--rev` recipe for installing a tool from a git branch
- `dependabot-auto-merge.yml` leaves a Dependabot PR that edits the workflow itself for a hand merge, read from the event's base and head SHAs, so a bumped token action never runs with the App's key before review. The check is a job of its own that the merge job needs, since the runner runs an action's `pre:` hook before a job's first step; it holds a compare at its 300-file limit and matches a renamed file under its old name. `dependabot.yml` keeps `create-github-app-token` out of the actions group, so its bump is held from its first push and holds no other bump
- `security.yml` calls the deny and vet gates, the semver preview, and mutation testing from `padamson/rust-ci-workflows`, pinned by SHA, so every repo runs one copy of them. Their checks report as `supply-chain / ...`, `semver-preview / ...`, and `mutation / ...`, and `scripts/github-settings.sh` and SETUP.md require the prefixed names
- `security.yml`: a semver preview on pushes and PRs, not required, comparing each publishable library crate with its latest crates.io release ahead of the tag-time gate; it passes over a crate whose manifest still names the placeholder repository
- SETUP.md: a `release tags` ruleset, admin bypass only, so a leaked merge-App key cannot push a release tag; vet fixes for a Dependabot PR land on `main` and reach the PR through `@dependabot rebase`
- `Cargo.toml`: a `[lints]` table with `unsafe_code = "deny"` and an empty clippy table
- `.claude/settings.json`: `com.apple.trustd.agent` beside `configd` in `allowMachLookup`, so a tool that verifies TLS through the macOS platform verifier (`cargo audit` 0.22) can fetch its database in-session
- CLAUDE.md: a `## Manual checks` section listing what a session cannot check (plain-terminal gates, GitHub and crates.io settings, what to read by eye)
- CLAUDE.md: before its first commit in a clone, a session checks that `.git/hooks/pre-commit` was generated by prek and asks for `prek install --overwrite` when it was not; `prek` runs as its own Bash call so the sandbox exclusion matches. The install is a Manual checks item, and SETUP.md's hook install is a checklist with the two verify steps
- `scripts/github-settings.sh`, run from a plain terminal, reports and with `--apply` sets the GitHub settings SETUP.md lists: Issues, auto-merge and head-branch deletion, code security, the `release tags` ruleset over every tag pattern in `release.yml` (a pattern a ruleset would read differently from the workflow is reported, not copied), branch protection on `main` (only once every required check has reported there), and the merge App's two Dependabot secrets, written whenever the App's flags are given so a new key can reach every repo before the old one is deleted. SETUP.md keeps the reasons and drops the `gh api` blocks; the release ceremony deletes the script with SETUP.md. SETUP.md no longer says to delete the App's old key when making a new one, which broke auto-merge in every other repo holding it, or to add an `admin:repo` scope, which does not exist
- `release.yml`'s publish job runs in a `release` environment, and `scripts/github-settings.sh` limits that environment to `release.yml`'s tag patterns, keeping any reviewers and wait timer already set on it. SETUP.md has the crates.io trusted publisher name the environment: the publisher checks the repository and workflow filename but not the ref, so without it a leaked merge-App key could push a branch with its own `release.yml` and publish from it, ruleset or not. It also has the crate's **Require trusted publishing for all new versions** box ticked, since the environment and the ruleset limit only the tokens the workflow mints and any crates.io API token with publish scope still publishes until it is
- `release.yml` publishes only once `cargo deny` and `cargo vet` pass on the tagged commit: a `Supply-chain gates` job calls the shared `supply-chain.yml` at the pin `security.yml` uses, after the semver check and beside the build matrix, so the gates are defined once and read advisories and imported audits at release time. A release with no `supply-chain/` store fails instead of skipping vet. A crate's first tag goes on the commit that adds its `audit-as-crates-io` policy, after the hand publish
- `release.yml` creates the GitHub Release in one `release` job, the last in the run, and `scripts/github-settings.sh` turns on immutable releases. Each build job attests its archive and uploads it as a workflow artifact, and the release job attaches them all with `gh release create`, which drafts, uploads, and then publishes. When each build job attached its own archive, the first to finish published the release, and with immutable releases on every later upload would have been refused. The release follows the crates.io publish, since an immutable release locks its tag and a publish that failed after it could not be retried under the same version. Build jobs hold `contents: read`, and a library crate (no binary) skips the archive, attestation and upload steps instead of letting a failed attestation pass
- `release.yml` runs its tests, release build and `cargo publish` with `--locked`, so a shipped binary and the publish's verify build use the committed `Cargo.lock` and a lock that disagrees with its manifests fails the release instead of being re-resolved
- Every `taiki-e/install-action` step sets `fallback: none`, so a tool missing from the action's manifest fails the step instead of installing through `cargo-binstall`, which checks no checksum. A comment at each workflow's first install step says to install such a tool with `cargo install --locked` instead
- `scripts/mutants.sh` diffs a root commit against git's empty tree, so a local run on a repo's first commit mutates the scaffold instead of failing with exit 128; a user-supplied base ref that does not resolve is now a hard error rather than a silent pass
- `scripts/mutants.sh --working` diffs uncommitted edits against `HEAD` (or a given ref), for gating a change before it is committed
- `scripts/mutants.sh` passes `--no-renames` to `git diff`, so a `git mv` produces a mutable diff instead of a green gate over unmutated code
- Pre-commit `cargo vet` hook: `files` regex now matches paths under `supply-chain/` (the end-anchored pattern matched nothing), and the hook skips until `cargo vet init` has run, mirroring the CI job
- `deny.toml`: `allow-wildcard-paths = true`, so versionless path deps of `publish = false` workspace members and dev-dependencies do not trip `wildcards = "deny"`
- CLAUDE.md: `--working` usage, the `-f <file>` trap, and the one-run-at-a-time rule for `mutants.out/`
- `Supply Chain Review` job checks for `supply-chain/audits.toml` before installing cargo-vet, so an uninitialized repo skips in seconds instead of installing the tool first
- `dependabot-auto-merge.yml`: enables squash auto-merge on every Dependabot PR (authored by Dependabot and pushed by it) behind the required status checks, using a GitHub App's token so each merge starts a push run on `main` (a `GITHUB_TOKEN` merge starts none). SETUP.md walks through the App, its two Dependabot secrets, and the Allow auto-merge and delete-head-branch settings
- Dependabot `cooldown` (7/14/7/3 days for cargo, 7 for actions) so bumps arrive after the cargo-vet import sets have audited them
- Dependabot groups for majors and for actions, plus a commented git-dependencies slot that must come first, so the weekly run opens at most four PRs and the auto-merge cascade (N PRs, O(N^2) CI runs) cannot start
- SETUP.md: require every PR-triggered job including `Mutation Testing (diff)`, and leave "require branches to be up to date" off, with the reasoning for both
- Initial project scaffold
- `.cargo/mutants.toml` with scoping guidance to keep `cargo mutants` runs tractable on real downstreams: `.cargo/` is the one path cargo-mutants reads (a root `.mutants.toml` is ignored silently) and the header says how to verify the config is live; `test_workspace = true` and no `--lib`, which skipped `tests/` integration targets and let cross-target kills survive; a commented nextest filterset as the speed lever and a commented `exclude_globs` for codegen output
- `test.yml` split: ubuntu-only `Lint` job covers fmt, clippy, doctest, and `cargo doc`; the cross-platform matrix (ubuntu/macos/windows) runs only `cargo build` + `cargo nextest run`
- Comments in `security.yml`, `.pre-commit-config.yaml`, and `deny.toml` documenting the `cargo audit --ignore` pattern keyed off `deny.toml`'s `[advisories] ignore` as source of truth
- CLAUDE.md / SETUP.md note on `prek install --overwrite` to avoid double-firing legacy pre-commit hooks
- MSRV-job comment on stubbing `include_bytes!` build artifacts via `touch` for downstreams that embed generated files
- Expanded `cargo vet import` list in SETUP.md to the seven well-known trusted orgs (bytecode-alliance, embark-studios, fermyon, google, isrg, mozilla, zcash), using the named-import form
- Per-PR workflow documentation in SETUP.md for handling Supply Chain Review failures on Dependabot PRs (never auto-regenerate exemptions in CI; certify vs. regenerate vs. reject)
- `cargo vet trust` section in SETUP.md: trust the publishers `cargo vet suggest` says your imported orgs already trust, once the import's `audits.toml` shows the entry's `end` is still ahead (the suggestion counts lapsed entries too), at `--criteria safe-to-deploy`, rerun with `--allow-multiple-publishers` for a crate with several publishers, and trust `github:<owner>/<repo>` for a crate published through Trusted Publishing. It names no default publishers, since which to trust is the user's call
- `scripts/mutants.sh` wrapper for `cargo mutants --in-diff`, with project-specific pre-setup placeholder, defaulting to `HEAD~1..HEAD`
- Two-job mutation testing in `security.yml`: a per-push/PR diff job using `cargo mutants --in-diff` (typical runtime seconds-to-minutes), and a full sweep on manual `workflow_dispatch` only — full-codebase runs don't scale to be scheduled
- `## Mutation testing` section in CLAUDE.md covering the local script + CI shape
- `/mutants.out/` and `/mutants.out.old/` added to `.gitignore`
- All Cargo cache steps in `test.yml` and `release.yml` switched from `actions/cache@v5` + manual key composition to `Swatinem/rust-cache@v2` + `shared-key`. Auto-derived key includes the rustc version (catches stale-binary panics across toolchain bumps), and pre-save cleanup keeps cache size in check. Release-job `shared-key` includes `matrix.target` so the two macOS cross-targets don't clobber each other.
